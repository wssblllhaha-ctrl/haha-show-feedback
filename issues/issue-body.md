## 现象

**iOS Safari** 上，当**系统开启深色模式**时，页面会被 Safari 按它自己的偏好重新上色，颜色明显变深一档。

最显眼的一处：**顶栏左侧那行小字（`A COLLECTION OF CURIOSITY`）会变成白色。** 整体背景、文字、次级文字也跟着变深，和站点自己的浅色主题配色不一致。

关掉系统深色模式就完全正常。

## 触发条件（比想象中宽）

| 操作 | 是否触发 |
| --- | --- |
| 系统深色关闭 → 打开网页 | 不触发 |
| 系统深色开启 → **刷新页面** | **触发** |
| 页面开着 → **不刷新，直接切系统到深色** | **触发** |

也就是：**只要当前系统处于深色模式，页面就会被上色**，不限于刷新。

## 已排除

1. **不是站点脚本** — 站点最早的第一版（当时还没有任何系统偏好跟随逻辑）就有这个问题。如果是 JS 读错偏好，首版没有那段代码时就不该复现。
2. **不是智能反转** — 智能反转是图片不反色、只反文字背景，且已是深色的界面不会被反成白色。实测第一次打开没有触发反转，图片也没有反色表现。
3. **不是 `prefers-color-scheme` 被读错** — 桌面端实测 CSS 变量全部正确（`accentSoft: #2d402f`、`bg: #161d19` 等），变量层没问题，问题只在 iOS Safari 的渲染层。

## 试过无效

| 办法 | 结果 |
| --- | --- |
| 把 `<meta name="color-scheme">` 钉成站点当前主题 | 无效 |
| 补 `@media (prefers-color-scheme: dark)` 的 CSS 兜底 | 无效 |
| 让站点跟随系统偏好（手动 > 系统 > 浅色兜底） | 无效 |

第二条值得说明：`<meta name="color-scheme" content="light dark">` 等于声明「我支持深色」，若 CSS 里没有对应的媒体查询，Safari 会自己动手上色。顺着这个推断补了媒体查询 —— **依然无效**。所以它的行为不是「你没适配我就替你适配」，更接近系统级自动配色，超出媒体查询能控制的范围。

## 另有两个我们自己的深色问题（尚未修，与上面是两回事）

1. **顶栏小标对比度过高** — `.brand-sub` 用的 `--muted: #a6b2a7` 放在 `#161d19` 上偏亮，深色下看起来像白色。本意是「次要信息」，视觉上却比正文还跳。
2. **`#crayon-grain` 滤镜疑似白色伪影** — 桌面实测正确，iOS 下疑似产生白色边缘。
