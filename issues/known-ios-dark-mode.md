# 已知问题：iOS 深色模式下页面被重新上色

## 现象

在 **iOS Safari** 上，当**系统开启深色模式**时，haha.show 的页面会被 Safari 按它自己的偏好重新上色，颜色明显变深一档：

- 顶栏左侧那行小字（`A COLLECTION OF CURIOSITY`）会变成白色 —— 这是最显眼的一处；
- 整体背景、文字、次级文字都跟着变深，和站点自己的浅色主题配色不一致。

关掉系统深色模式就完全正常。

## 触发条件（比想象中宽）

原本以为只有刷新才触发，实测比这宽：

| 操作 | 是否触发 |
| --- | --- |
| 系统深色关闭 → 打开网页 | 不触发 |
| 系统深色开启 → **刷新页面** | **触发** |
| 页面打开着 → **不刷新，直接把系统切到深色** | **触发** |

也就是说，**只要当前系统处于深色模式，页面就会被上色**，不限于刷新这一个动作。

## 已排除的怀疑

### 1. 不是站点脚本造成的

**站点最早的第一版（当时还没有任何系统偏好跟随逻辑）就有这个问题。**

这一条直接洗清了脚本：如果是我们的 JS 读错偏好或写错 `data-theme`，那么首版不存在这段代码时就不该复现。既然首版也复现，问题在浏览器侧。

### 2. 不是「智能反转」

iOS 的智能反转（设置 → 辅助功能 → 显示与文字大小）有两个可辨认的特征：

- **图片不反色**，只反文字和背景；
- **已经是深色的界面不会被反成白色**。

实测第一次打开网页时并没有触发反转，且页面里的图片没有反色表现，所以可以排除智能反转。

### 3. 不是 `prefers-color-scheme` 被读错

我们实测过桌面端（Edge，深色稳态）的 CSS 变量，**全部正确**：

```
accentSoft : #2d402f
fillStroke : rgb(45, 64, 47)
frameStroke: rgb(180, 207, 155)
subColor   : rgb(166, 178, 167)
bg         : #161d19
```

变量层没有问题，问题只出现在 iOS Safari 的渲染层。

## 试过但无效的办法

| 办法 | 结果 |
| --- | --- |
| 把 `<meta name="color-scheme">` 钉成站点当前主题（`light` / `dark`） | 无效 |
| 补 `@media (prefers-color-scheme: dark)` 的 CSS 兜底 | 无效 |
| 让站点跟随系统偏好（三级优先级：手动 > 系统 > 浅色兜底） | 无效 |

其中「补媒体查询」这条值得展开说一下，因为**它的失败恰好说明了问题性质**：

`<meta name="color-scheme" content="light dark">` 等于向浏览器声明「我支持深色」。但如果 CSS 里没有对应的 `@media (prefers-color-scheme: dark)` 规则，Safari 就会认为「你自己不画，那我替你画」，于是动手上色。

顺着这个推断，我们补了媒体查询 —— 结果是**依然无效**。所以 Safari 在这里的行为并不是「发现你没适配就替你适配」，更接近于系统级的自动配色，超出了媒体查询能控制的范围。

## 目前的做法

- 站点保留了「跟随系统偏好」的逻辑（手动选择 > 系统偏好 > 浅色兜底，跟随系统时不写入 `localStorage`）。对部分浏览器有效，对 iOS Safari 这个具体问题无效。
- **不再继续投入排查**。这是平台侧的行为，绕过成本高于影响面，记录在此，等以后环境变化或找到确切的平台文档再说。

## 顺带记两个我们自己的、尚未修的深色问题

这两个和上面的 Safari 强制变色是**两回事**，是我们自己配色的问题：

1. **顶栏小标对比度过高** — `.brand-sub` 用的是 `--muted: #a6b2a7`，这个值放在 `#161d19` 的底色上偏亮，深色下看起来像白色。本意是「次要信息」，视觉上却比正文还跳。
2. **`#crayon-grain` 滤镜疑似白色伪影** — 该滤镜由 `feTurbulence + feDisplacementMap + feColorMatrix + feComposite operator="in"` 组成，桌面实测正确，但在 iOS 下疑似产生白色边缘。
